# FreeHISTORIA

Бесплатная пошаговая историческая стратегия на русском языке. Выберите стартовый год, существующую державу или собственное государство. Торговля приносит доход, реформы влияют на стабильность, посольства открывают путь к унии. Карта отражает территории союза, летопись сохраняет решения.

Игра использует календарь и обработку территориальных событий Open Historia. Движок работает по правилам и обходится без платных API и моделей ИИ. Год можно ввести вручную от −999999 до 999999. После 1 года до н. э. сразу наступает 1 год н. э. Для старта в периоде Cliopatria используются границы по выбранному году. Для более ранних дат используется ближайший из 54 обзорных срезов Historical Basemaps. Для 2025 и 2026 годов доступны отдельные карты и справочники регионов. Для более позднего старта используется карта 2026 года. Точный год старта сохраняется независимо от даты карты. Последний год календаря доступен для старта, продвижение дальше недоступно.

## Локальный запуск

Требуются Node.js 22.18 или новее и tar. Зависимости npm устанавливать не нужно.

```sh
npm run dev
```

Панель доступна на http://localhost:5173, API на http://127.0.0.1:8787. Команда собирает статику и запускает два отдельных HTTP-сервера. После изменения исходников перезапустите команду. Для проверки выполните `npm test`.

## Мультиплеер

Оба игрока подключают один API в настройках панели. В разделе «Мультиплеер» создатель выбирает год, имя и державу и передаёт друзьям код или ссылку из лобби. Приглашённый выбирает свободную державу. Когда в комнате есть хотя бы два игрока, создатель начинает партию. Очередь идёт в порядке входа, год завершается после последнего игрока. Дипломатия между игроками меняет двусторонние отношения. Уния присоединяет свободную державу. Карта и летопись общие. Можно закрыть вкладку и вернуться со своего браузера через список комнат.

Для игры по домашней сети запустите `npm run lan` и откройте выведенный адрес локальной сети на обоих устройствах. Для доступа нужны порты WEB_PORT и API_PORT (по умолчанию 5173 и 8787). Обычный `npm run dev` привязан к loopback. Для игры через интернет разместите API по HTTPS и настройте API_URL для Pages.

Сетевой интерфейс использует тот же Bearer-ключ игрока. GET и POST /v1/rooms перечисляют и создают комнаты. POST /v1/rooms/preview и /join принимают invite, вход также требует name и nation. GET /v1/rooms/{id} возвращает состояние участнику, параметр since позволяет проверять изменения. POST /v1/rooms/{id}/start и /turns требуют revision текущего состояния. Сервер проверяет очередь и записывает изменение с проверкой версии в SQLite.

## Исторические данные

Импортированы 13 797 записей о 1 637 политических образованиях из Cliopatria. Программа проверяет включительное условие FromYear ≤ год ≤ ToYear. Для каждого совпадения доступны контур, оценка площади, родительская держава, составные территории и внешние идентификаторы, когда источник их содержит. Геометрия упрощена для мировой карты. Датировка означает интервал реконструкции. Старые партии сохраняют прежние границы.

Современные выпуски доступны и в одиночных кампаниях, и в комнатах. Карта 2025 года содержит 258 стран и территорий по выпуску Natural Earth / geo-countries от 10 апреля. Карта 2026 года содержит 260 по выпуску Country Boundary Map от 23 июля. Спорные территории показаны согласно правилам соответствующего источника. Это даты публикации карт. Справочники Country State City от 21 декабря 2025 и 19 ноября 2026 содержат соответственно 5 217 и 5 276 названий регионов, сопоставленных с территориями карты. Карточки показывают столицу, валюту, площадь и регионы при наличии записи. Визуальные контуры доступны на уровне стран и территорий, для регионов приведены списки.

`GET /v1/history?year=2026&nation=Germany` возвращает карточку и даты источников в `provenance`. Для сборки обеих современных карт и справочников запустите `python3 scripts/import-modern.py /tmp/freehistoria-atlas`. Импортёр использует закреплённые версии и кэширует загруженные файлы.

GET /v1/history?year=1453 возвращает список держав и записей. Параметры nation и facts=1 добавляют досье выбранной державы. Атлас и игра запрашивают Wikidata по идентификатору из территориального справочника, проверяют годы начала, окончания и указания события, учитывают смену должностных лиц в течение года. Состав по атласу и административные утверждения Wikidata показаны отдельно. На сервере результаты сохраняются в SQLite на семь дней. Биография правителя доступна в раскрываемом разделе и через GET /v1/history/person/{Wikidata-QID}. Карточка содержит должности и датировки, титулы, династию и сведения о жизни, которые указаны в источнике. Для стартовых сценариев включены сохранённые ответы. При недоступности источника панель показывает статус и даёт повторить запрос. Во время игры карта следует решениям участников, а историческая справка запрашивается для текущего игрового года.

Импорт исходного архива воспроизводится командой `python3 scripts/import-cliopatria.py cliopatria.geojson.zip`. Встроенные досье обновляются командой `node scripts/refresh-facts.js`. Версия источника и лицензия указаны в CREDITS.md.

## Личный API-ключ

В меню «ИИ-провайдер» выберите Chat Completions, Anthropic Messages, Gemini или произвольный JSON API. Введите полное имя модели, полный адрес метода и ключ. Для собственного формата настройте заголовок, префикс, JSON-шаблон с {{prompt}} и {{model}}, а также путь к тексту результата, например choices.0.message.content. Поддерживаются HTTP JSON POST и ключ в заголовке. Для других механизмов авторизации или потоковых протоколов нужен совместимый шлюз.

Ключ находится в sessionStorage вкладки до её закрытия или удаления через настройки. По умолчанию браузер обращается к провайдеру напрямую. Для провайдеров с ограниченным CORS можно явно выбрать отправку через игровой сервер. Сервер пересылает ключ только на разрешённый endpoint и не записывает его в SQLite. Встроены адреса OpenAI, Anthropic, Gemini, OpenRouter, Groq, Mistral и DeepSeek. Дополнительные полные адреса администратор указывает через запятую в PROVIDER_ENDPOINTS. Используйте доверенный HTTPS-сервер для ключей. Приказ разрешается в одно из игровых действий, правила и очередь проверяются отдельно. Ключи каждого участника индивидуальны.

## Серверный API

```sh
API_HOST=0.0.0.0 API_PORT=8787 DATA_DIR=./data \
ALLOWED_ORIGINS=https://YOUR-ACCOUNT.github.io npm run api
```

Разместите процесс за HTTPS reverse proxy. В ALLOWED_ORIGINS перечислите разрешённые источники через запятую, без пути репозитория и завершающего слеша. Для DATA_DIR используйте постоянный диск. API хранит кампании в SQLite. Панель генерирует случайный 256-битный ключ для каждого адреса сервера и хранит его в localStorage. Очистка данных браузера удаляет ключ доступа и локальные партии. В многопользовательской установке настройте лимиты запросов и объёма хранилища на стороне хостинга.

| Запрос | Результат |
| --- | --- |
| GET /v1/health | Проверка доступности без ключа |
| GET /v1/campaigns | Список кампаний владельца ключа |
| POST /v1/campaigns | Создание по целому year и строке nation. Необязательный UUID v4 в id позволяет безопасно повторить запрос |
| GET /v1/campaigns/{id} | Состояние и летопись |
| POST /v1/campaigns/{id}/turns | Годовой ход. Передайте expectedTurn, action и target для дипломатии и унии |

Для кампаний передавайте `Authorization: Bearer <64 строчных шестнадцатеричных символа>`. Тело POST имеет тип application/json. Допустимые действия — trade, reform, diplomacy, unite. В target передаётся исходное имя державы из списка nations стартового года. Старые сохранения продолжают использовать shared/catalog.json. Сервер отвечает 409 при конфликте версии. Повторно загрузите кампанию, чтобы увидеть сохранённый ход.

### Приказы в свободной форме

Если на сервере работает Ollama с загруженной моделью, задайте OLLAMA_MODEL с её именем при запуске API. OLLAMA_URL по умолчанию равен http://127.0.0.1:11434. В подключённой панели появится действие «Свой приказ · ИИ». Модель получает приказ, год, состояние державы и последние три события. Она выбирает одно из четырёх игровых действий и описывает результат. Стоимость действий, условия унии и запись хода проверяет сервер. При недоступности модели можно выбрать обычное действие.

## GitHub Pages

1. Поместите проект в свой репозиторий, в ветку main.
2. В Settings → Pages → Build and deployment выберите GitHub Actions.
3. Чтобы игроки по умолчанию подключались к вашему серверу, задайте переменную репозитория API_URL с публичным HTTPS-адресом API без /v1. Разрешите источник Pages на сервере.
4. Отправьте изменения в main или вручную запустите workflow FreeHISTORIA Pages. Он проверит игру, соберёт dist и опубликует панель. Все пути относительные, включая карты и изображения.

Если API_URL пуста, панель запускает игры в браузере. Через «Настройки» можно выбрать сервер и проверить соединение. Сохранения привязаны к выбранному режиму и адресу сервера.

Для проверки размещения вручную выполните `npm run build` и откройте dist через любой статический HTTP-сервер. Например, `python3 -m http.server 5173 --directory dist`. При сборке в артефакт добавляется архив исходников для скачивания в разделе «О проекте».
